# Инструкции по работе с M53-Colpo

Этот файл описывает публичную самостоятельную редакцию. Инструкции для пользователей находятся в [README](README.md), [руководстве администратора](public/docs/ADMIN.md) и [руководстве врача](public/docs/DOCTOR.md).

## Структура проекта

- `crates/domain` и `crates/contracts` содержат модель протокола и контракты API.
- `crates/server` и `migrations` содержат API и схему PostgreSQL.
- `crates/client` и `prototypes/gpui-editor` содержат общую логику клиента и настольный интерфейс.
- `public/windows`, `public/linux`, `public/deploy` и `public/release` содержат установщики, инструкции развёртывания и инструменты выпуска.

## Разработка и проверки

- Для публичного клиента и сервера используйте feature `standalone`. Первый вход проходит через собственный сервер установки. Рабочий процесс должен оставаться доступным с локальными учётными записями без 1С.
- При исправлении дефекта сначала воспроизведите его тестом, затем внесите минимальное исправление и повторите проверки. Сохраняйте проверки доступа, утверждения протокола, очередей и совместимость сохранённых данных.
- Используйте версию Rust из `rust-toolchain.toml` и параметр `--locked`. Установочные пакеты для пользователей собираются отдельно от инструкций для разработчиков.

```sh
cargo test --locked -p m53-server --features standalone --lib
cargo test --locked -p m53-client --no-default-features --features standalone --lib --tests
python3 -m unittest discover -s public/release -p 'test_*.py'
python3 -m unittest discover -s public/windows -p 'test_*.py'
```

Сквозной тест `public/deploy/test_standalone_http.py` поднимает временную PostgreSQL и проверяет первый запуск, вход, ручной протокол и утверждение. Соберите сервер с feature `standalone` перед тестом. Для тестов Windows используйте [инструкцию сборки](public/windows/BUILD.md) и сценарий `public/windows/test-setup.ps1` на Windows.

## Данные и выпуск

- Используйте синтетические данные и отдельную временную базу в тестах, примерах и отчётах об ошибках. Рабочие базы, снимки, пароли и ключи храните вне Git и пакетов выпуска.
- Собственный код распространяется по [AGPL-3.0-only](LICENSE). Сохраняйте уведомления сторонних компонентов и предоставляйте исходники, соответствующие опубликованным сборкам.
- Выпуск по тегу выполняется через `.github/workflows/release.yml`. До публикации сверяйте состав дистрибутивов, SHA-256 и исходники зависимостей через `public/release/verify_release.py`. Ссылки в README должны вести на опубликованные файлы того же выпуска.
